# frontend

React + Vite + TypeScript + Tailwind CSS. **카드가 화면의 중심**이다 (채팅이 아님).
라벨: `to-frontend`

## 실행

```
cd frontend
npm install
npm run dev        # http://localhost:5180
npm run typecheck  # 타입 검사
npm run build      # 타입 검사 + 프로덕션 빌드
```

첫 화면은 로그인이다. 계정·역할 선택 없이 **"데모 체험하기" 버튼 하나**로 바로 들어간다 (목업. 실제 인증은 B2, 연동은 F10).

## 메뉴 구성

```
홈          대시보드
내 업무      기록하기 · 카드 덱 · 자료
판단        계획 비교 · 질문하기
인수인계     기록하기(인수인계 쓰기) · 점검 · 카드 덱 · 자료 · 확인 모드
```

계정은 한 종류라 모두에게 같은 메뉴가 보인다. 인계자·후임자는 계정의 종류가 아니라 인수인계 한 건에서 맡는 입장이다. 프로젝트 선택은 없고, 프로젝트는 카드의 이름표다.

## 구조

| 위치 | 내용 |
|---|---|
| `src/index.css` | **디자인 토큰** (아이보리 바탕 + 진한 브라운 테두리). 색은 이 파일 한 곳에서만 정의한다 |
| `src/components/layout/` | 사이드바, 상단바, 레이아웃 |
| `src/pages/` | 화면 (로그인, 계획 비교, 카드 덱·상세, 자료, 대시보드, 아직 만들지 않은 화면의 자리) |
| `src/components/cards/` | 카드·배지·과정 타임라인·대체 흐름 부품 |
| `src/lib/nav.ts` | 메뉴 구성. 화면 코드(A~J)와 만드는 단계(F번호)가 같이 적혀 있다 |
| `src/lib/data.ts` | `contracts/examples/`의 예시 데이터를 직접 읽는다 (F9에서 가짜 API로 교체) |
| `src/lib/AppState.tsx` | 로그인한 사용자, 사이드바 접힘 상태 |
| `src/mocks/` | 가짜 API (F9에서 추가) |

## 규칙

- 예시 데이터는 `contracts/examples/` 한 곳만 쓴다. frontend 안에 따로 mock 데이터를 만들지 않는다.
- 화면은 판정·카드 생성 문장을 만들거나 바꾸지 않는다 (에이전트의 일). 받은 결과만 보여준다.
- 상태·판정은 색만으로 구분하지 않고 아이콘과 글자를 함께 쓴다.
- 카드는 두 종류다: 업무 기록 카드(`kind=work`, 과정 포함)와 인수인계 카드(`kind=handover`, 원본 카드 연결).

| F8 | 점검·확인 모드·질문하기·대시보드 보강 (권장) | |
