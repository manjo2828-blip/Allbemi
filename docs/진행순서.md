# 진행순서

# 3주 개발 순서 (단계 번호 포함)

서비스는 **두 기능**으로 구성됩니다. **기능 1. 내 업무 기억**(업무를 모두 기록·저장하고, 그 안의 결정을 과정까지 카드로 정리. **기록은 넓게 받고 구조화는 결정에만**, 서비스의 본체는 결정 카드)과 **기능 2. 인수인계**(업무 기록에서 인수인계 카드 초안 생성, 점검, 확인)입니다. 판단 기능(계획 비교·질문하기)은 두 기능이 함께 씁니다. 설계 근거는 [`docs/두기능_설계안.md`](docs/두기능_설계안.md)와 README에 있습니다.

단계 번호는 분야별로 붙였습니다.

| 접두사 | 분야 |
|---|---|
| **C** | 공통 준비 |
| **F** | 프론트엔드 |
| **B** | 백엔드 |
| **AG** | 에이전트 (README의 산출물 번호 A1~A7과 겹치지 않게 `AG`로 표기했습니다) |
| **E** | 데이터·평가 (README의 산출물 번호 A·R이 완료 기준에 함께 적혀 있습니다) |
| **P** | 마무리 |

**구분**: 필수 / 권장 / 선택은 앞에서 정한 3주 범위 기준입니다.

## 3. 프론트엔드 (F)

**사이드바 (확정)**

```
홈          대시보드
내 업무      기록하기 · 기록 목록 · 카드 덱 · 자료
판단        계획 비교 · 질문하기
인수인계     기록하기(인수인계 쓰기) · 점검 · 카드 덱 · 자료 · 확인 모드
```

계정은 한 종류이고 모두에게 같은 메뉴가 보입니다(인계자·후임자는 인수인계 한 건에서 맡는 입장이지 계정의 종류가 아닙니다). 메뉴명은 짧게, 화면 제목은 풀네임으로 구분합니다. 프로젝트 선택은 없고 프로젝트는 카드의 이름표입니다. 개발용 화면(RAG Lab 등)은 서비스 프론트엔드에 넣지 않습니다.

| 순서 | 일차 | 만들 것 | 완료 기준 | 구분 |
|---|---|---|---|---|
| **F1** | 1 | 프로젝트 세팅 (React+Vite+TS+Tailwind), 디자인 토큰(색·서체·간격). 올빼미 마스코트는 보류 | 빈 화면에서 색·서체가 적용됨 | 필수 (완료) |
| **F2** | 1 | 카드 컴포넌트: 결정, 근거, 버린 대안, 상태 색(유효 초록·폐기 회색 취소선·대체 화살표), 확신도, "확인 필요" | 상태별 카드 4종이 보임 | 필수 (완료) |
| **F3** | 2 | **화면 B 장면 ① 계획 비교**: 입력창, 내 카드와 전임자 카드 나란히, 판정 배지 4종, 기각 이유 | MongoDB 시나리오로 🚫 배지가 뜸 | 필수 (완료) |
| **F4** | 2 | **화면 A 카드 덱·상세**: 상태별 구분, 시간순, 원문 펼치기, 첨부 자료(📎·미리보기·다운로드), 자료 화면 | 카드 클릭 → 상세 → 원문·자료 확인 | 필수 (완료) |
| **F5** | 3 | **구조 개편 + 상태 시각화**: **로그인 화면("데모 체험하기" 버튼 하나로 계정 없이 입장, 로그아웃)**, 사이드바를 새 구조로 변경(그룹), 카드 종류(`kind`)별 덱·자료 분리, 카드 상세에 **과정 타임라인**과 인수인계 카드의 원본 카드 링크, **화면 D 상태 시각화**(대체 화살표·폐기 표시), 계획 비교 결과에 "내 기록 / 인수인계" 라벨 | 새 사이드바로 두 영역이 나뉘어 동작, 번복 관계와 과정이 보임 | 필수 |
| **F6** | 3 | **화면 C 내 업무 기록하기**: 로그 붙여넣기 + 파일 드롭존, 카드 뒤집힘 생성 연출(결정과 과정), 카드마다 연결 자료·"연결 확인 필요" | 붙여넣기 → 카드 생성 연출, 파일 연결 표시 | 필수 (1차 완료) |
| **F6-2** | 4 | **기록하기 개편 + 기록 목록** (내 업무): 기록은 항상 저장(결정이 없어도 정상 결과 "기록만 저장됨"), 안내 문구를 "오늘 한 일을 자유롭게 적어요"로 변경, 결과를 **원문과 카드 나란히**(결정 문장 진하게·과정 연하게), **카드 개봉 연출로 결정 유무 표시**(결정 있음: 카드가 뒤집히며 펼쳐짐 / 없음: 빈 카드가 열리며 "기록만 저장됨"), 문장 선택해 "결정 카드로 만들기", 후보 카드 확정·"결정 아님", **기록 목록**(날짜순, "결정 N장 / 기록만" 배지), 카드 덱·상세·계획 비교 결과의 카드 개봉 효과(움직임 줄이기 설정 존중) | 결정 없는 기록도 저장되고, 카드가 개봉되듯 나타남, 기록 목록에서 원문과 카드 확인 | 필수 |
| **F7** | 4 | **화면 E 인수인계 쓰기**: 범위 선택, AI 초안 카드(원본 카드 연결), 다듬기, 인수자 메모 (초안 카드도 개봉 효과로 나타남) | 업무 기록 카드에서 만든 초안이 보이고 원본으로 이동 | 필수 |
| **F8** | 5 | **인수인계 점검 · 확인 모드 · 질문하기 · 대시보드 보강**: 점검(빈 자리·불일치·완성도 게이지·인계할 자료), 확인 모드(카드를 한 장씩 넘길 때 개봉 효과), 질문 패널, 대시보드 | 점검·확인·질문 화면이 가짜 데이터로 동작 | 권장 |

## 9. 정해진 것과 아직 정할 것

**정해진 것**
1. 프론트엔드 기술: React + Vite + TypeScript + Tailwind
2. 디자인 방향: 아이보리 바탕에 갈색 테두리, 진한 브라운. 올빼미 마스코트는 보류
3. 사이드바 구조와 프로젝트 선택 제거, 개발용 화면 제외
4. **기록 방식**: 업무는 일지 전체를 기록으로 저장하고 구조화(카드·과정)는 결정에만 한다. 결정 카드가 본체이고 일반 기록은 원문 보관과 근거 역할
5. **카드 개봉 연출**: 결정 찾기 결과(있음/없음)와 카드를 확인하는 모든 곳에서 카드가 개봉되듯 나타남. 움직임 줄이기 설정이면 연출 없이 바로 표시

**아직 정할 것**
1. **후임자의 업무 기록 열람 방식**: 인계자가 카드별로 공개를 허용할지, 인계 범위 전체를 공개할지 (C5·B2에 영향)
2. **같은 결정이 두 카드에 있을 때의 표시**: 인수인계 카드를 우선 표시하고 원본을 접어서 연결(현재 가정)할지 (F5·AG4에 영향)
3. **GPU 환경**과 **LLM API 월 예산** (AG11, E8~E9 범위를 결정)
4. **사용자 테스트 대상** (17~19일차 가능한 사람 3명)
